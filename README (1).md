# קו הזמנות טלפוני + לוח מילוי הזמנות

מערכת MVP למכירה טלפונית לקהל שמזמין דרך הקו (כמו מודל משנת יוסף):
פרסום בעיתון → הלקוח מתקשר לקו → מזמין בהקשות והקלטות → משלם בסליקה מאובטחת של ימות →
ההזמנה נכנסת ללוח בקרה, ומשם אתה מבצע את המילוי מול הספק (עליבאבא) בחשבון שלך.

## מה יש כאן

```
server.js          קו ה-IVR (yemot-router2) + API לניהול + הגשת לוח הבקרה
store.js           אחסון קטלוג + הזמנות בקובץ JSON (בלי תלויות native)
payment.js         העברה לשלוחת הסליקה המאובטחת של ימות
public/index.html  לוח בקרה (RTL) — הזמנות נכנסות, מילוי, קטלוג
```

## איך זה עובד — השרשרת

1. **פרסום.** מודעה בעיתון: "להזמנה חייגו 03-XXXXXXX שלוחה N".
2. **הקו.** המתקשר שומע את המוצרים והמחירים, בוחר מוצר, כמות, מקליט שם וכתובת.
3. **תשלום.** הקו מעביר אותו לשלוחת סליקה מאובטחת של ימות. **הכרטיס מוקלד אצל ימות, לא אצלך.**
4. **הזמנה.** ההזמנה נשמרת ומופיעה בלוח הבקרה כ"חדשה".
5. **מילוי.** אתה פותח את ההזמנה, לוחץ "פתח בעליבאבא", מזמין **בכרטיס של העסק שלך**,
   שולח לכתובת הלקוח, ומעדכן סטטוס (הוזמן → נשלח → הושלם).

## הרצה מקומית

```bash
npm install
ADMIN_PASSWORD=הסיסמה_שלך BUSINESS_NAME="שם העסק" npm start
```

- לוח בקרה: `http://localhost:3000/admin/`
- הקו: ימות פונה ל-`http://localhost:3000/yemot`

בהרצה הראשונה הקטלוג ריק — היכנס ללוח הבקרה → "קטלוג מוצרים" → הוסף מוצרים
(קוד, שם, מחיר מכירה, עלות בעליבאבא, קישור המוצר). המחיר והעלות נותנים לך את הרווח לכל פריט.

## חיבור לימות המשיח

בפאנל ימות, במערכת שלך:
1. הגדר **שלוחה עם `api_url`** שמצביע ל-`https://<your-app>/yemot` (השלוחה הראשית של המכירה).
2. הגדר **שלוחת סליקה** ("גביית תשלום") עם ספק סליקה ישראלי (טרנזילה וכו').
   שים את מספר/נתיב השלוחה במשתנה `YEMOT_PAY_EXTENSION` (ברירת מחדל `/pay`).
3. (מומלץ) בשלוחת הסליקה, אחרי הצלחה, הוסף **קריאת API החוצה** אל:
   `https://<your-app>/paid?order=<מספר ההזמנה>&ref=<אסמכתא>`
   כך ההזמנה מסומנת "שולם" אוטומטית. אין בקריאה הזו מספר כרטיס — רק אסמכתא.

## פריסה ב-Render

- New → Web Service, חבר את הריפו.
- Build: `npm install` · Start: `npm start`
- Environment: `ADMIN_PASSWORD`, `BUSINESS_NAME`, `YEMOT_PAY_EXTENSION`.
- ⚠️ **דיסק אפמרי:** בתוכנית החינמית קובץ ה-JSON נמחק בכל דיפלוי/הפעלה מחדש.
  לפרודקשן: חבר **Render Disk** בתשלום (והגדר `DATA_DIR` לנתיב הדיסק), או עבור ל-DB חיצוני.

## אבטחת תשלום — לא לעקוף (חוקי + חובה)

- **אין** לאסוף מספר כרטיס בהקשות בקו ולשמור/להעביר אותו. זו הפרת PCI-DSS וחשיפה פלילית.
- הלקוח מזין כרטיס **רק** בסליקה המאובטחת של ימות; אתה מקבל אסמכתא בלבד.
- את עליבאבא אתה משלם **בכרטיס/חשבון של העסק**, נפרד מהלקוח. הלקוח משלם לך — אתה משלם לספק.

## הערה על אמון (זה האינטרס העסקי שלך)

דרופשיפינג עם מרווח הוא לגיטימי — אף חנות לא חושפת את הספק שלה. מה שהורס עסק בקהילה סגורה זה
טענות שקריות: "מיוצר בארץ", "משלוח מיידי" כשזה 3 שבועות מסין, או מוצר שלא תואם לתיאור.
תיאור כן + זמן אספקה ריאלי + מרווח סביר = לקוחות חוזרים והמלצות. שקר אחד בקהילה כזאת = סוף העסק.

## מה חסר ל-MVP הזה (השלב הבא)

- מעקב אחר הזמנה בקו ("להאזנה לסטטוס ההזמנה הקישו…") לפי מספר טלפון.
- הגבלת ניסיונות/ולידציה בקלט (כבר יש `digits_allowed` בבחירת מוצר).
- מסד נתונים אמיתי (SQLite/Postgres) במקום קובץ JSON.
- אימות אמיתי ללוח הבקרה (כרגע סיסמה משותפת).
- אוטומציית מילוי מול עליבאבא (יש DS API אבל דורש אישור; כרגע המילוי ידני מהלוח).
